Four design approaches — and how to tell them apart

ApproachWhat it does (course wording)Clue in the question
Brute forceTry every candidate solution, keep the best."every order / route", n! candidates
Divide and conquer Lec 4.1Top-down: divide an instance into smaller instances, conquer each by recursion, combine (if needed).n/2, n/3 pieces that don't overlap: binary search, mergesort, quicksort
Dynamic programming Lec 6.1Bottom-up: solve small instances first, store the results, look them up. Needs a recursive property.n − 1, n − 2 sub-instances that overlap; "try every option using stored answers"; a table: binomial coefficient, Fibonacci
Greedy Lec 8.1A sequence of decisions, each the best at that moment, never undone. May not be optimal."always take the cheapest / smallest now and keep it": coins, Huffman, Prim, Kruskal, Dijkstra

Justify from the formula or strategy itself (e.g. "one half-size instance, no overlap"; "cheapest edge chosen and never undone"), then say why the others don't fit.

Greedy: the three steps in every iteration (Lec 8.1)

  • Selection procedure — choose the locally best next item.
  • Feasibility check — can it be added without breaking the rules?
  • Solution check — is the instance solved?

Coins 12c, 10c, 5c, 1c for 16c: greedy 12+1+1+1+1 = 5 coins, optimal 10+5+1 = 3. Greedy is simpler, but only sometimes optimal; DP is optimal when the principle of optimality applies.

The four greedy algorithms

Kruskal Lec 9.1 — MST
Input: undirected, weighted, connected graph. F = ∅; one disjoint subset per vertex; sort edges in nondecreasing order. Select the next edge → if its ends are in different subsets: merge them, add the edge to F; otherwise skip (it would make a cycle). Solved when all subsets are merged (n − 1 edges). No start vertex.
Prim Lec 9.1 — MST
F = ∅, Y = {v1}. Select the vertex in V − Y nearest to Y (joined to Y by an edge of minimum weight — one edge, not a path); add it to Y and that edge to F. Solved when Y == V. Any start vertex gives the same total weight.
Dijkstra Lec 9.2 — single-source shortest paths
Directed or undirected, weights ≥ 0. Y = {source}, F = ∅. Select the vertex in V − Y with the shortest path from the source using only vertices in Y as intermediates; add it to Y and the edge on its shortest path to F; update the others. Solved when Y == V. Similar to Prim, but compares whole path lengths from the source.
Huffman Lec 8.2 — optimal prefix code
Priority queue: lowest frequency = highest priority. Repeat n − 1 times: remove p, remove q; new node r with r->left = p, r->right = q, frequency p + q; insert r. Code = path from the root, left 0, right 1. "No feasibility check"; "no solution check — solution is obtained when i = n − 1".

Huffman: rules and counting bits

  • Prefix code: no codeword is the beginning of another. Characters sit only at leaves.
  • Total bits = Σ (frequency × code length).
  • Fixed-length = (number of characters in the file) × ⌈lg k⌉ bits, for k different characters (6 characters → 3 bits). The lab photos' "original" uses 8 bits per character.
  • Encoded ÷ original × 100 = the compressed size (%); space saved = 100 − that. The lab photos call the first one "% compression".
  • Reverse (table → tree, 2025 Q1): node weight = sum of its children; every merge must take the two smallest nodes in the queue at that moment; the left child is the one removed first (≤ the right). Each merge gives a condition on the unknown.

Common traps

  • Prim ≠ Dijkstra. Prim: cheapest single edge from Y. Dijkstra: shortest total path from the source.
  • MST ≠ shortest paths. A–B 2, B–C 2, A–C 3: the MST weighs 4; Dijkstra from A keeps A–C, total 5.
  • Kruskal: a skipped edge doesn't end the run — carry on until n − 1 edges are in F.
  • Dijkstra: directed edges go one way; never update a vertex already in Y; give the path, not just the distance.
  • Huffman: a merged node can be smaller than an original character — put it back in the queue by weight.
  • DP vs D&C: "shrinks by one" is not the test; overlap is.
  • Out of scope: knapsack, TSP, Floyd.

Write your assumptions on the paper

  • Huffman: "Smaller weight on the left (the node removed first), 0 = left, 1 = right. On equal weights I took …".
  • Ties in Dijkstra, Prim or Kruskal — the course states no tie rule: "A and C tie at 3; I took A first." Any tied choice is correct; say which.
  • Dijkstra: "An entry is replaced only when the new distance is strictly shorter."
  • Kruskal: list your sorted edges, so the marker can see your order.

Time complexities Textbook — not in the slides
